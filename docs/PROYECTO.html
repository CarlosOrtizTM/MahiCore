0.3 Crear el proyecto (Fase 0)

Ejecuta estos comandos en orden. Las versiones están fijadas a propósito: Next.js 14 usa React 18, y las versiones más nuevas de algunas librerías exigen React 19 y fallan al instalar.

bash — inicialización del proyecto
# 1. Crear el proyecto base (Next.js 14, App Router, TypeScript, Tailwind)
#    create-next-app ya inicializa un repositorio git.
npx create-next-app@14 mahicore --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"
cd mahicore

# 2. Dependencias de la aplicación (versiones compatibles con React 18)
npm install @prisma/client@5 next-auth@4 lucide-react zod
npm install three @react-three/fiber@8 @react-three/drei@9

# 3. SheetJS se instala desde su CDN oficial (el paquete "xlsx" de npm está desactualizado)
npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz

# 4. Dependencias de desarrollo
npm install -D prisma@5 tsx @types/three

# 5. Inicializar Prisma con PostgreSQL
npx prisma init --datasource-provider postgresql

# 6. Crear docker-compose.yml y .env.example (sección 0.4) y guardar el avance
git add -A && git commit -m "Fase 0: estructura base del proyecto"

SECCIÓN 01

Resumen ejecutivo

MahiCore es una plataforma interna tipo CMDB (Configuration Management Database) diseñada para equipos de infraestructura y telecomunicaciones de Tech Mahindra. Unifica el inventario físico, los enlaces de red, las credenciales seguras y la visualización espacial en una sola herramienta.

  • Inventario físico jerárquico: Registro exhaustivo de dispositivos (switches, routers, firewalls, cámaras, APs) con asignación de espacio (Sede → Piso → Sala → Rack → Unidad U).
  • Documentación de enlaces: Trazabilidad punto a punto de puertos físicos y medios de transmisión (Fibra, UTP Cat6, Coaxial).
  • Gemelo digital 3D interactivo: Entorno espacial WebGL para planificar montaje en racks, calcular colisiones y trazar cableados de forma visual.
  • Bóveda de credenciales: Almacenamiento seguro con cifrado simétrico AES-256-GCM y soporte para referencias UUID de Vaultwarden.
  • Auditoría inmutable: Registro centralizado en AccesoLog de toda acción administrativa o consulta de contraseñas.
  • Procesamiento masivo: Motor de ingestión e importación automatizada a partir de archivos Excel legados.

SECCIÓN 04

Modelo de datos (PostgreSQL vía Prisma)

4.1 Diagrama entidad-relación

Entidades, llaves primarias y foráneas, tipos y relaciones del esquema. Los campos en gris son opcionales o tienen valor por defecto.

4.2 Reglas de integridad

  • Borrado en cascada: eliminar una Sede o un Piso elimina también sus Salas, Racks y Equipos.
  • Equipos y enlaces: al borrar un Equipo se eliminan sus Puertos y, con ellos, sus Enlaces.
  • Un puerto, un enlace activo: un puerto puede aparecer como A o como B, así que un @unique por columna no alcanza. El endpoint POST /api/enlaces verifica dentro de una transacción que ninguno de los dos puertos tenga ya un enlace con activo = true. Desconectar un cable no borra la fila: marca activo = false y guarda fechaBaja, así queda el historial.
  • Sala y rack coherentes: si un Equipo tiene rackId, su salaId debe ser la sala de ese rack. La API lo valida al crear y al mover equipos.
  • Posición en el rack: un equipo ocupa desde uInicio hasta uInicio + alturaU − 1. Antes de guardar, la API comprueba que ese rango no se cruce con otro equipo del mismo rack y que no pase de unidadesU. Las coordenadas XYZ son solo para la vista 3D.
  • Auditoría preservada: borrar una Cuenta no borra sus registros en AccesoLog; la llave foránea queda en nulo (onDelete: SetNull).
  • Valores cerrados con enums: tipo de equipo, estado, medio del enlace y rol son enum de Prisma, no texto libre. Así un error de tipeo como "swtich" falla al compilar y no llega a la base de datos.

SECCIÓN 05

Autenticación, roles y seguridad

5.1 Autenticación y sesiones

La autenticación usa NextAuth.js con un proveedor de credenciales local, sin servicios externos. Las contraseñas de los usuarios se guardan como hash PBKDF2-SHA512 con 600.000 iteraciones y un salt aleatorio de 16 bytes.

  • Duración de la sesión: JWT con maxAge de 1 hora que se renueva con la actividad. La sesión se cierra tras 1 hora sin uso.
  • Bloqueo por intentos: tras 5 intentos fallidos seguidos, bloqueadoHasta se fija 15 minutos en el futuro y el login se rechaza hasta esa hora. Un login correcto reinicia intentosFallidos.
  • Cambio obligatorio: los usuarios creados por el seed o por un administrador tienen cambioPendiente = true y deben definir su propia contraseña en el primer ingreso.

5.2 Matriz de roles y accesos (RBAC)

* Requiere reautenticación: el usuario vuelve a escribir su propia contraseña antes de ver la credencial.

5.3 Dónde se verifica el acceso

El middleware.ts solo redirige al login a quien no tiene sesión; es una comodidad de navegación, no una barrera de seguridad. En 2025 se publicó una vulnerabilidad de Next.js (CVE-2025-29927) que permitía saltarse el middleware con una cabecera manipulada. Por eso cada Route Handler verifica la sesión y el rol por su cuenta, con un helper como este:

src/lib/guard.ts
// src/lib/guard.ts
import { getServerSession } from "next-auth";
import { authOptions } from "@/lib/auth";

const NIVEL = { lector: 1, editor: 2, administrador: 3 } as const;
type Rol = keyof typeof NIVEL;

export class HttpError extends Error {
  constructor(public status: number, message: string) { super(message); }
}

export async function requireRole(minimo: Rol) {
  const session = await getServerSession(authOptions);
  if (!session?.user) throw new HttpError(401, "Sesión no válida");
  const rol = session.user.role as Rol;
  if (NIVEL[rol] < NIVEL[minimo]) throw new HttpError(403, "Permisos insuficientes");
  return session.user;
}

// Uso en src/app/api/equipos/route.ts
export async function POST(req: Request) {
  const user = await requireRole("editor");   // primera línea de cada handler
  // ...validar con Zod, guardar y registrar en AccesoLog
}

Ocultar un botón en la interfaz tampoco es seguridad: el DoD exige probar cada endpoint con peticiones directas (Thunder Client o Postman) usando un usuario sin permisos.

5.4 Cifrado AES-256-GCM y revelado seguro

Las contraseñas de infraestructura se cifran con AES-256-GCM antes de guardarse. El valor almacenado en passwordReferencia tiene el formato iv:tag:cifrado en hexadecimal, con un IV nuevo de 12 bytes en cada cifrado. Si passwordEsBoveda es verdadero, el campo guarda en cambio el UUID del ítem en Vaultwarden.

Para revelar una contraseña se usa POST /api/cuentas/[id]/revelar con la contraseña del usuario en el cuerpo JSON ({"confirmPassword": "..."}). Es POST y no GET con cabecera porque las URLs y cabeceras suelen quedar en logs de servidores y proxies. Cada revelado, exitoso o no, genera un registro ver_credencial en AccesoLog.

5.5 Qué hace inmutable a la auditoría

  • No existe ningún endpoint de UPDATE ni DELETE para AccesoLog; la API solo inserta y lee.
  • El registro se escribe en la misma transacción que la acción auditada: si falla el log, falla la acción.
  • El campo detalle nunca guarda contraseñas ni valores cifrados, solo qué se hizo y sobre qué registro.

SECCIÓN 07

Módulos funcionales

7.1 Dashboard (/)

Se renderiza con Server Components para que cargue rápido. Muestra contadores clave, credenciales que vencen en los próximos 15 días (según fechaVencimiento), enlaces pendientes de verificar en campo y el acceso a la importación desde Excel.

7.2 Inventario de equipos (/equipos)

CRUD completo de dispositivos. Al crear un equipo se generan sus puertos según el tipo: switch 24, router 4, firewall 8; los demás tipos arrancan sin puertos y se agregan a mano. Datos variables como IPs o VLANs de gestión van en el campo configuracion (JSON).

7.3 Ubicaciones y responsables (/ubicaciones, /responsables)

Administración de la jerarquía Sede → Piso → Sala → Rack y del directorio de personas a cargo de equipos y cuentas. Son los primeros módulos a construir (Fase 3), porque todo lo demás depende de ellos.

7.4 Topología (/topologia)

Se construye en dos etapas:

  • 7A — Vista 2D del rack: el rack se dibuja como una columna de 42 unidades con HTML y CSS. El usuario ubica equipos eligiendo la unidad inicial, y la API rechaza posiciones que se crucen. Esta etapa ya cumple los criterios de aceptación de posición y colisión.
  • 7B — Gemelo digital 3D: con three y @react-three/fiber, los racks se muestran en el espacio de la sala, los equipos se arrastran con gizmos y los enlaces se dibujan como cables entre puertos. Reutiliza la misma validación de la 7A.
Figura 7.4A — Render tridimensional de gabinetes, switches y gizmos de traslación CANVAS 3D

7.5 Cuentas y accesos (/cuentas)

Bóveda de credenciales de plataformas, servidores y consolas cloud. Cada cuenta puede guardar la contraseña cifrada localmente o solo el UUID del ítem en Vaultwarden. Los listados nunca incluyen la contraseña; para verla hay que reautenticarse (sección 5.4).

7.6 Auditoría (/auditoria)

Solo para administradores. Muestra los eventos de AccesoLog del más reciente al más antiguo, con filtros por usuario, acción y rango de fechas. Es de solo lectura.

Referencia de API (Route Handlers)

Todas las rutas exigen sesión. "Acceso mínimo" es el rol más bajo que puede usarla; los roles superiores también pueden.

POST/api/equiposeditorCrear equipo y generar sus puertos según el tipo. Valida sala/rack y unidades U.
PUT/api/equipos/[id]editorActualizar datos, posición en el rack o coordenadas 3D.
DELETE/api/equipos/[id]editorEliminar equipo con sus puertos y enlaces.

9.1 Respuestas y códigos HTTP

CódigoCuándo se usa
200 / 201Lectura correcta / recurso creado.
400El cuerpo no pasa la validación de Zod.
401No hay sesión, o la contraseña de confirmación es incorrecta.
403Hay sesión, pero el rol no alcanza.
404El recurso no existe.
409Conflicto: puerto ya enlazado, unidades U ocupadas, email o nombre duplicado.

Todos los errores responden con el mismo formato, para que el frontend los muestre de forma uniforme:

respuesta de error (JSON)
{
  "error": "Las unidades 10 a 11 del rack R-02 ya están ocupadas por SW-CORE-01",
  "codigo": "UNIDADES_OCUPADAS"
}

SECCIÓN 10

Variables de entorno

Copia .env.example como .env y completa los valores. El archivo .env nunca se sube al repositorio.

.env
# Conexión a PostgreSQL (mismos datos que docker-compose.yml)
DATABASE_URL="postgresql://mahi_admin:mahi_local_dev@localhost:5436/mahicore?schema=public"

# Secreto para firmar los JWT de sesión
NEXTAUTH_SECRET="<resultado del comando 1>"
NEXTAUTH_URL="http://localhost:3000"

# Llave AES-256: exactamente 64 caracteres hexadecimales
ENCRYPTION_KEY="<resultado del comando 2>"

Genera los secretos con estos comandos en vez de inventarlos:

bash — generar secretos
# 1. NEXTAUTH_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# 2. ENCRYPTION_KEY (64 caracteres hex)
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
No cambies la ENCRYPTION_KEY con datos cargados: las contraseñas cifradas con la llave anterior ya no se podrán leer. En producción esta llave se guarda en un gestor de secretos, no en un archivo.

Puesta en marcha local

Pasos para arrancar el proyecto en un equipo nuevo, por ejemplo después de clonar el repositorio:

terminal — arranque local
# 1. Instalar dependencias
npm install

# 2. Crear el .env y generar los secretos (sección 10)

# 3. Levantar PostgreSQL
docker compose up -d

# 4. Crear las tablas aplicando las migraciones
#    La primera vez, en el proyecto nuevo: npx prisma migrate dev --name init
npx prisma migrate dev

# 5. Cargar los datos iniciales
npx prisma db seed

# 6. Arrancar el servidor en http://localhost:3000
npm run dev

Cada vez que modifiques schema.prisma, crea una migración nueva con npx prisma migrate dev --name descripcion-del-cambio y súbela a git junto con el cambio.

SECCIÓN 13

Criterios de aceptación (Definition of Done)

  • Cada Route Handler verifica sesión y rol. Probado con peticiones directas (Thunder Client o Postman) usando un usuario sin permisos: responde 401 o 403.
  • Ningún listado ni respuesta incluye contraseñas en texto claro; solo se revelan con reautenticación.
  • Toda mutación y todo revelado de credencial genera un registro en AccesoLog, en la misma transacción.
  • Borrar equipos, salas o sedes elimina en cascada lo que corresponde según la sección 4.2.
  • Dos equipos no pueden ocupar la misma unidad U del mismo rack, ni un equipo puede pasar del límite del rack. La API responde 409.
  • Un puerto solo puede tener un enlace activo a la vez. Desconectar conserva el historial.
  • La importación de Excel reporta las filas con error como advertencias y procesa el resto del archivo.
  • El login se bloquea 15 minutos tras 5 intentos fallidos seguidos.
  • Los usuarios del seed deben cambiar su contraseña en el primer ingreso.
  • npm run build termina sin errores de TypeScript ni de ESLint, y las migraciones están en el repositorio.
